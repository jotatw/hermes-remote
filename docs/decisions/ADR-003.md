# ADR-003: Cliente único PWA (não separar apps)

## Status

Aceito

## Contexto

O v2 precisa cobrir três grandes funções: chat com o Hermes, dashboard de
status do servidor e comandos remotos (dormir/acordar, backup, logs). Uma
opção considerada foi separar em dois apps (chat vs servidor), cada um
focado e com tela mais limpa.

## Decisão

Um **único PWA** com navegação por abas (Início / Chat / Servidor),
usável tanto na rede local quanto remotamente via Tailscale com a mesma
interface — só muda o endpoint.

## Consequências

- 1 deploy, 1 service worker, 1 cache, 1 manifest para manter.
- Estado e componentes compartilhados entre views (ex.: ver status do
  servidor e perguntar no chat na mesma sessão).
- Interface mais densa — mitigada com abas bem definidas e mobile-first.
- Manutenção proporcional ao tamanho real do app (1 pessoa, 2 backends).

## Alternativas consideradas

- **Apps separados (chat vs servidor)**: telas mais limpas, mas 2 deploys,
  2 caches, 2 manifests e estado não compartilhado — manutenção dobrada
  para uma pessoa, contra o princípio de "simples primeiro".
