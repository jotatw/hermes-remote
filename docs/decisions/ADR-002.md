# ADR-002: Gateway único no homeserver

## Status

Aceito

## Contexto

O ecossistema tem duas máquinas: **homeserver** (sempre ligado, 24/7) e
**notebook** (roda o Hermes Agent, nem sempre ligado). O cliente (PWA no
celular) precisa se comunicar com ambas. No v1, o cliente falava direto com
o Hermes API server no notebook, e o homeserver era apenas um proxy CORS
frágil. Isso criava dois pontos de contato e expunha o notebook diretamente
à rede.

## Decisão

Todo o tráfego do cliente passa pelo **homeserver como gateway único**.
O homeserver serve o PWA estático, responde chamadas de status/energia com
dados próprios, e faz proxy reverso para o notebook quando necessário
(chat, code review, automações). O cliente nunca sabe o IP do notebook.

## Consequências

- Cliente tem um único endpoint (homeserver) — muda só entre rede local e
  Tailscale para acesso remoto.
- Autenticação, CORS e TLS centralizados num ponto só.
- Notebook fica isolado na rede (não precisa de porta exposta).
- O gateway precisa de lógica de fallback offline (quando notebook dorme,
  o chat retorna indisponível em vez de timeout genérico).

## Alternativas consideradas

- **Cliente fala direto com cada máquina**: mais simples em teoria, mas
  expõe o notebook, duplica auth/CORS, e requer que o cliente saiba o
  IP de cada máquina.
- **Proxy reverso (Caddy) no homeserver**: complementar, não substituto.
  O gateway é uma camada de aplicação, não só de rede.
